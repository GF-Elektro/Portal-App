# G&F Elektro Portal – Main Process Improvements

**Scope**: `src/main.js`  
**Electron version**: 35.0.1  
**Target outcome**: Enhanced security, stability, maintainability without behavior changes

---

## Priority 1 — Critical Fixes (Implement First)

### 1.1 Fix Firebase Auth Domain Allowlist
- **Line 118–129**: `'content-firebaseappcheck'` is invalid; should be `'content-firebaseappcheck.googleapis.com'`
- Consider using exact hostname matching instead of `includes()` for security
- Recommended: `['accounts.google.com', 'accounts.youtube.com', 'googleapis.com', 'gstatic.com', 'firebaseapp.com', 'firebaseauth.com', '__/auth', 'portal.gfelektro.com', 'gfelektro.com', 'apis.google.com', 'oauth2.googleapis.com', 'securetoken.googleapis.com', 'identitytoolkit.googleapis.com', 'content-firebaseappcheck.googleapis.com']`

### 1.2 Restrict Permission Handler
- **Line 384–388**: `permissionCheckHandler` returns `true` for ALL permissions — this is too broad
- Should only return `true` for explicitly allowed permissions: `notifications`, `media`, `clipboard-read`, `clipboard-sanitized-write`
- Return `false` for anything else

### 1.3 Add Notification Error Handling
- **Line 241–248**: Wrap `new Notification()` in try-catch to prevent crashes if notification fails
- Check if `Notification.isSupported()` before showing

### 1.4 Debounce Reload Events
- **Line 197–201 & 189–194**: Multiple reload triggers on auth completion can cause rapid cycling
- Implement simple debounce flag or use `setTimeout` to coalesce events

## Priority 2 — Security & Stability

### 2.1 Enable Session Partition
- Add `session: session.fromPartition('persist:portal')` to `webPreferences`
- Isolates app storage from other Electron apps and Chromium profiles

### 2.2 Enable Renderer Process Reuse (Electron ≥27)
- Call `app.allowRendererProcessReuse()` early in `app.on('ready')`
- Reduces memory footprint and startup time

### 2.3 Add Linux Stability Flags
- **Line 86–95**: In `webPreferences`, add `disable-dev-shm-usage: true` for Linux (prevents /dev/shm exhaustion in Docker/CI)

### 2.4 Validate `shell.openExternal` URLs
- **Line 168, 213**: Validate URLs against a safe protocol list (`http:`, `https:`) to prevent protocol injection
- Example: `if (!url.startsWith('http')) return { action: 'deny' };`

### 2.5 Update `loadURL` Usage
- **Line 102**: For Electron 35+, consider using `loadURL` with `{ extraHeaders: '...' }` or keep as-is (still valid)
- No urgent change needed, but monitor Electron deprecations for future versions

## Priority 3 — Code Quality & Architecture

### 3.1 Extract Constants & Configuration
- Move `PORTAL_URL`, `APP_NAME`, `AUTH_ALLOWED_DOMAINS` to a separate `config.js` module
- Enables environment-specific overrides (dev/staging/prod)

### 3.2 Refactor Window Creation Logic
- Move `isAuthOrAllowedURL()` outside `createWindow()` for testability
- Consider splitting `createWindow()` into smaller functions (setupWebPreferences, setupNavigationHandler, setupAuthHandlers)

### 3.3 Consolidate Navigation Event Handlers
- **Line 180–194**: `will-navigate` and `did-navigate` do the same thing — consolidate into one handler per window
- Remove redundant check in child window `closed` event (already handled by `will-navigate`/`did-navigate`)

### 3.4 Centralize Icon Loading
- `getIconPath()` and `getTrayIcon()` have duplicate `try/catch` blocks — extract common fallback logic
- Ensure consistent 16×16 sizing for Windows tray (current implementation is correct)

### 3.5 Use Named Functions for Debugging
- Convert inline arrow functions in event listeners to named functions for better stack traces
- Especially for IPC handlers and window event listeners

### 3.6 Add JSDoc Annotations
- Document `isAuthOrAllowedURL`, `showWindowFromTray`, `hideWindowToTray` with brief descriptions and parameter types
